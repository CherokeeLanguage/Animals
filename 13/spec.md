# Spec #13 — Restore the win-linux-mac desktop channel: content-complete 5.12 hotfix jar rebuild and itch re-push

Repo: CherokeeLanguage/Animals (single-repo scope). Source of requirements: the developer's defect report "the windows dist version appears to be defective... missing the entire game engine and supporting graphics" (2026-11-09), the removal direction for the deployed jar (2026-11-09), the hotfix-branch direction "create a branch to cover these changes should we need to apply future hotfixes against 5.12; the assumption is that the app will be migrated to godot at some future point, so the hotfixes only apply to the 5.12 libGDX version" (2026-11-09), and the build-fix/testing directive "fix the build in the temp checkout and build the jar for testing" (2026-11-09). Paired record: **CherokeeLessons.com#22** — the itch page's channel-table row for `win-linux-mac` (struck 2026-11-09 with the removal note; revised in place at this spec's execution).

## Problem

Every desktop jar this repo ever shipped — the published 5.12 the site's download page served since 2021, and the first itch deployment — was never content-complete. Verified 2026-11-09 by building tag 5.12 in a clean checkout and inspecting the output: the `desktop:dist` task packages only the runtime classpath, so the jar carried the engine (2,274 classes, 28 natives) and 28 non-class entries — libGDX's built-in `arial-15` font pair plus engine metadata (GLSL shaders, maven poms, gwt descriptors) — while `android/assets/` (457 challenge images, 421 challenge audio takes, fonts, music, backdrops) never entered the jar: zero game content. The standalone launch crashed at first content load: `Couldn't load file: images/challenges/ani.png (Internal)`. The tag's own `build-release.sh` runs the same task, so the defect is structural to the line, not transport damage. The developer removed the defective jar from the itch page's win-linux-mac channel after deployment exposed it (dashboard-side deletion verified 2026-11-09: page lists the android file only).

The fix is proven and committed on the `hotfix/5.12` maintenance branch — created 2026-11-09 at the developer's direction as the 5.12-line hotfix vehicle (base: tag 5.12, `678cd19`; commit `36720a1`: `from files(project.assetsDir)` in the dist task — one line). The full build procedure for the line is proven end-to-end in the temp checkout (JDK 8 — system JDKs 21/25 are too new for Gradle 6.5; the tag's own prep chain; the tree's Gradle 6.5 wrapper) and produced a 59,642,548-byte content-complete jar (3,560 entries: 2,274 classes, 28 natives, 1,258 data files incl. `images/challenges/ani.png`).

What remains: rebuild the release jar from the hotfix branch per the proven procedure, gate on acceptance (launch with content), and re-push the win-linux-mac channel to the paired itch project through the repo's existing itch tooling.

## Scope

The Animals repo: the `hotfix/5.12` line (its committed packaging fix; the rebuild procedure), the operator config for the re-push, and the push execution through `itch-push.sh`. The paired itch project's channel-table record (CherokeeLessons.com#22) is revised in place at execution time as a sibling-record edit — this spec owns no CherokeeLessons.com files (site pages, site repo).

Deploy-source facts (verified 2026-11-09): the rebuilt artifact is a **new** jar built from `hotfix/5.12` — not the published 2021 jar, which is defective and removed. The challenge content sources (`Assets/challenges/pictures/` 457 tracked PNGs + 2 tracked JPGs, `Assets/challenges/audio/` 7 tracked take-dirs) are in git at the tag; the runtime content (`android/assets/images/challenges/`, `android/assets/audio/challenges/`) is generated by the prep chain and untracked — a fresh clone has neither, which is why the published jar lacked it (the 2021 build machine had run the preps). `android/assets/text/challenge-images.txt`/`challenge-audio.txt` are tracked lists naming the generated files; the preps regenerate them (fresh-run diffs against the tracked 2021 versions exist and stay uncommitted — build outputs on this line).

## Requirements

- **R-1 — Content-complete rebuild.** The release jar rebuilds from `hotfix/5.12` per the proven procedure: JDK 8; the tag's prep chain (`Assets/challenges/prep_pictures.py`, `Assets/challenges/prep_audio.py`, `android/assets/00-make-all-plist.sh`, the `git log --simplify-merges --pretty=format:"%ad [%h]:%d %s" --abbrev-commit --date=short > android/assets/text/git-changelog.txt` line); the tree's own Gradle 6.5 wrapper (`core:build desktop:dist`). The jar carries the full asset set (challenge images and audio, fonts, music, plists, changelog) with engine classes and natives intact.
- **R-2 — Acceptance before push.** The rebuilt jar launches with content on the developer's desktop: main menu and level select reached, challenge data loads, no content-missing crash. No push before acceptance.
- **R-3 — win-linux-mac re-push.** The operator config (`itch.conf`, gitignored) re-enables the jar path pointing at the rebuilt artifact, and `itch-push.sh` — which by design pushes both channels on every run — executes the re-push via butler: the jar goes to `cherokee-language/cherokee-language-animals:win-linux-mac`, and the android push is an idempotent content-identical re-push of the already-deployed APK (no-op patch; the APK is unchanged and already deployed and verified). No version claims (butler's auto-numbering stands). The tracked tree changes not at all — the script runs as committed on #11's line.
- **R-4 — Live page verification.** The itch page's download section lists the restored win-linux-mac file: filename matching the rebuilt jar's, displayed size consistent with its byte size.
- **R-5 — Sibling record.** CherokeeLessons.com#22's channel-table row for `win-linux-mac` is revised in place to restored state (pointing at this spec's record) once R-4 verifies.

## Out of scope

- The plist/list regen diffs (tracked 2021 outputs vs fresh prep runs) — build outputs stay uncommitted on this line; a pinning decision rides only if the line ever needs a tagged release flow.
- The Godot migration — it replaces this line entirely at some future point; `hotfix/5.12` never merges forward as a feature.

## Approach

The hotfix branch carries the fix (committed `36720a1`, build-verified). Rebuild per the procedure; the developer's acceptance run gates the push; `itch.conf`'s jar line re-enables with the rebuilt artifact's path (local, gitignored — no tracked-file change); `itch-push.sh` pushes (butler channel pushes are idempotent and re-pushable — the channel was deleted dashboard-side, so the first push recreates it); the live page verifies per R-4; the #22 record revision closes the loop. `hotfix/5.12` remains the 5.12-line maintenance branch for any further hotfixes.

Alternatives weighed: building from `master` — rejected, master is the Godot port with no libGDX build surface (its gradle roots are IDE stubs) and the developer's direction scopes hotfixes to the 5.12 line; re-packaging the published 2021 jar by injecting assets — rejected, a rebuild from the fixed task produces the artifact reproducibly and the injected-jar route is unverifiable against the line; pushing before acceptance — rejected by R-2, the removal happened because an unverified artifact shipped.
